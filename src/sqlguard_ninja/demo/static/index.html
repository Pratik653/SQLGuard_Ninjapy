    About this playground
    
        
    SQLGuard Ninja checks SQL produced by an AI agent before it runs. It checks the SQL against a policy: which tables and columns a role may read, how classified data may be used, and which tenant's rows are in scope. It is open source (Apache-2.0).
    
        
    What happens when you press “Check & run”
    
        
      
          
    1. The query is parsed and analysed for the selected role and store group. Nothing in the SQL can change the role or tenant.
      2. 
          
    2. If any rule blocks it, you see why and how to fix it. Nothing runs.
      3. 
          
    3. If it is allowed, it runs against a small synthetic retail database. The database is in memory, read-only and private to this session. Its authorizer allows only table reads and safe functions, and engine limits and a time budget apply.
      4. 
        
    
        
    What this demo is not
    
        
      
          
    • It is not a security guarantee. Static analysis is one layer. Production systems still need database permissions, row-level security and timeouts.
      • 
          
    • The benchmark numbers are internal. See the Benchmarks tab.
      • 
          
    • No real customer data exists here. Names, emails and card numbers are fabricated, and card numbers use a published test range.
