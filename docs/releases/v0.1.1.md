# SQLGuard Ninja v0.1.1

Documentation and governance patch release. **The enforcement behaviour is identical to v0.1.0.**
v0.1.0 remains published and unchanged on PyPI.

## Fixed
* The README's documentation links now work on the PyPI project page (they were relative in 0.1.0).

## Added
* [Limits of static SQL analysis and dialect support](https://github.com/Pratik653/SQLGuard_Ninjapy/blob/main/docs/security/STATIC_ANALYSIS_LIMITS.md)
* [Benchmark bias review](https://github.com/Pratik653/SQLGuard_Ninjapy/blob/main/docs/guides/BENCHMARK_BIAS_REVIEW.md):
  the v1 results reflect consistency with the engine's own semantics, not independent detection quality.
* [External dataset intake rules](https://github.com/Pratik653/SQLGuard_Ninjapy/blob/main/benchmarks/datasets/external/README.md); no external cases yet.
* CODEOWNERS and branch protection on `main`.

## Known limitations (unchanged)
* No benchmark cases for restricted functions (server file access, sleep, dynamic SQL,
  administrative functions) or system catalogs (`pg_catalog`, `information_schema`,
  `sqlite_master`, `sqlite_schema`). The rules ship and run, but their detection is not measured.
* Writes are denied. Only PostgreSQL and SQLite are supported. No guarantee against SQL injection or data leakage.

## Installation

```bash
python -m pip install sqlguard-ninja==0.1.1
python -m pip install "sqlguard-ninja[all]==0.1.1"
```

PyPI: https://pypi.org/project/sqlguard-ninja/0.1.1/
